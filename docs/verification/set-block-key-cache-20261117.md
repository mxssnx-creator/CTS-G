# Set Block relation-key cache

The collision-safe relation key is pure for the same Set, lane, side and relation group. Cache its encoding with a bounded 16,384-entry LRU; this does not cache guard verdicts, configuration state, fills or P&L. Eviction only requires re-encoding the same key. A test checks escaped identities and verifies the capacity after more unique keys than the limit.

In a local repeated-key microbenchmark (three trials, two relations, 100,000 calls), the pre-isolation implementation's median was 0.038 seconds, the uncached scoped implementation was 0.461 seconds, and this cached implementation was 0.068 seconds. These measurements are host-specific, were taken while other work was running, and do not establish an end-to-end scan or exchange execution latency. Cold keys can still incur encoding costs. Run `python3 scripts/benchmark_set_block_relation_keys.py` (or `--cold`) for a local comparison.

For 300 synthetic active parents across 50 symbols, 100 cycles of candidate decisions with persistence disabled took 0.677 seconds uncached and 0.528 seconds cached (median of three); both produced the same 30,000 candidate decisions. This excludes disk, network and the rest of the engine. Conversely, 9,000 changing Set identities exceeded the cache and took 0.219 seconds cached versus 0.108 uncached for three passes; an all-miss 20,000-call run took about 0.155 seconds cached versus 0.080 uncached. A separate Python allocation trace reported about 5.9 MB with all 16,384 entries occupied for the tested short identifiers. Profile the actual workload and memory before drawing system-level conclusions.
