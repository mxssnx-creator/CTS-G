# Secure, Minimal preset

This is a saved, editable candidate for a small balance. Loading it changes the Settings form only; it takes effect on a connection only after the user saves it and a compatible engine has been verified. It is not a claim of profitable or low-drawdown performance.

**31 October correction:** The automatic-hold engine used for the checkpoint results below spliced counterfactual tapes and could include overlapping positions or omit eligible entries. The original preset and expanded-pack checkpoint counts, PFs and sample counts are withdrawn as evidence. The stage oracle checked membership on that same flawed tape, so its agreement does not validate the underlying positions. The archived JSON files carry the same warning. See the [causal-hold audit](causal-hold-forward-audit-20261031.md) for the corrected replay and its remaining limitations.

- Scan up to 50 USDT-M symbols, retaining symbols with open positions; admit at most two simultaneous positions and one per group. The current scanner ranks exchange maximum leverage first and quote volume second, even though this preset trades at 1×; this is not evidence of liquidity or low drawdown.
- Use 1× leverage, no Block or DCA additions, a 2% of equity entry-notional budget and a 5 USDT ceiling at the quoted decision price. Strict sizing skips an order when the exchange minimum exceeds that budget or equity is unknown. Actual fill prices can differ; a small account may have no eligible order sizes.
- Use a 3% modeled initial stop-plus-cost filter and a 3% session-equity halt for new entries. Trailing Sets also have a 3% arm, give and initial-stop grid limit. These do not guarantee realized loss or account drawdown: gaps, actual fees and slippage, exchange rounding, delayed/rejected stops, liquidation and existing positions can exceed them. The drawdown halt stops new entries; it is not an automatic liquidation.
- Use the requested PF defaults (1.05 / 1.10 / 1.15 / 1.25 / 1.50 and Signals 1.30) and 12 hours of history. The Base long window reads up to 50 closes and requires at least 12; the Base short, Main and Real windows require their full configured samples. Focus the current CTS-G grid on steps 2–8 and Short Range steps 2–6. CTS-G's existing PF classes describe last-N window sizes; they are not yet CTS-A-O's strategy-range identities, and the CTS-A-O Signal source is not connected.
- The preset disables the current Negative lane because it can bypass the positive Main PF gate and does not implement the requested independently simulated opposite-direction strategy. This changes the preset, not the systemwide default; the independent inverse strategy remains unfinished.
- The modeled cost budget considers selected-symbol exchange rates plus the configured slippage allowance when rates are available; exchange-reported fills and commissions take precedence. A missing rate remains an estimate. Neither fees nor current x01 positions have been checked on the exchange in this environment.

Recorded Set-close statistics expose fee-source counts, explicitly marked ownership counts and a PF status separate from the legacy numeric sentinel. The full-window flag is a sample-size check, not proof that ownership or fees were verified. A reported aggregate fee does not by itself establish the fee attributable to the original Set component. These changes do not change the existing entry gate or reconcile legacy positions.

With the 0.12% fallback cost, constructing the preset creates 822 Sets, of which 810 satisfy the modeled stop filter. Those are configuration counts, not PF validations or evidence of tradable symbols. Historical quality, per-context stage isolation, performance for 50 actual symbols, venue order sizing and stops, owned positions, x02, and the x01 account must be verified before a live start.

The earlier faster replay used a global hold despite this preset enabling automatic holds. Its 0/9,864 Base result and empty execution describe that **different hold policy**, not the exact preset; the simulated gate/rank self-check did not test hold-selection parity. The replay JSON is retained with a warning. The faster simulator now refuses automatic-hold settings rather than silently misrepresenting them, and checks cache provenance before reuse.

A subsequent audit scored 12 hourly historical checkpoints using the actual engine then in the draft. Its automatic-hold tape was later found to contain impossible overlaps. Its archived outcomes and the matching stage oracle are retained for traceability only; they cannot establish Base, Main or Real results.

The configured PF control currently classifies **window length**, not the CTS-A-O strategy range: the Base last-50 window asks the Long 1.50 floor even for the Short Range pack. With this option on, the separate Short Range minimum does not override that window-size policy. The requested independent Micro/Minimal/Short range identities and their range-based policy still need integration and causal revalidation. This finding does not justify weakening a gate or starting x01.

The current CTS-G Negative lane retains original-direction shadow trades opened during a Main dip. It is not the separately simulated, opposite-direction Main strategy required by the CTS-A-O operator architecture. Historical Set evidence is also pooled across symbols and sides. Neither the stage-oracle match nor these statistics resolve those identity and progression differences.
